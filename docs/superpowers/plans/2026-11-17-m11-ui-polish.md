# M11 UI polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every screen (Puzzles, Results, Progress, Play vs Bots, and a new Settings page) uses consistent spacing, type and components. Every screen works at 1024×768 with no horizontal scroll. No known polish bug is left from M6–M10 or from the M11 visual audit. The look stays the current dark felt: no new palette or visual direction.

**Architecture:**
- **Tokens, not a new design system.** `tokens.css`, `tokens.answer.css` and `tokens.results.css` stay. A fourth file, `tokens.ui.css`, adds what this milestone needs:
  - layout tokens: bar height, page widths, control heights;
  - component tokens: control border, button, select, badge, range fill cap;
  - type roles and the 11 px text floor.

  Existing values are reused wherever they exist.
- **A few shared primitives**, only where the audit shows real inconsistency. Today buttons are styled in 7 CSS modules, selects in 2, badges in 4 and panels in about 8.
  - The primitives are `Button`, `Select`, `Badge`, `Panel`, `Toggle` (moved out of `TopBar`) and `ConfirmDialog`, in `frontend/src/components/ui/`.
  - Each screen adopts them in its own task. The last task sweeps what's left.
  - A small `lib/contrast.ts` checks every colour claim this plan makes.
- **A Settings page** at `/settings` takes:
  - the display toggles (Pot odds, Show profile);
  - the Shortcuts toggle;
  - the default Villain profile;
  - the daily goal;
  - the explanations model status, with "Check again".

  The top bar keeps only each page's own controls, so it fits in one row at 1024 and at 1280.
- **The backend changes in three small ways:**
  - one route, `POST /api/settings/llm-check`, re-probes the local model past the probe cache;
  - the explainer gets a "hand" noun for play decisions;
  - one invariant test pins the play pot award.
- **The table screens get one shared layout module**, used by both Puzzles and Play:
  - a top grid holds the table, the answer panel and the Action panel;
  - a full-width row below holds the results details;
  - the Action panel is no longer sticky, so it can never cover the details.

**Tech Stack:** as today (FastAPI, React 19, Vite, Vitest, Playwright). No new dependencies.

## Global Constraints

- **Product rules (CLAUDE.md) hold.**
  - No shown number may disagree with the API. Every number on screen is an API field, formatted by the shared helpers in `lib/format.ts` (and `lib/stats.ts`, `lib/play.ts`). The browser adds no arithmetic beyond formatting.
  - Amounts are shown in bb. The API works in chips (bb = 2 chips).
  - The range shown is the range graded.
  - A formula shown reproduces the API's number.
- **No LLM numbers.** The explainer change is wording only. The M8 guardrail and its tests are unchanged and must pass.
- **Puzzle outputs don't change.**
  - `backend/tests/puzzle/test_golden.py` and every `frontend/src/test/fixtures/attempt_*.json`, `puzzle_*.json`, `stats*.json`, `history_page.json` and `settings.json` stay byte-identical.
  - Only the play fixtures are regenerated (Task 1, with `--play-only`).
- **Keep the look.** Colours come from the existing tokens. `tokens.ui.css` either aliases existing tokens or adds layout metrics. There are two exceptions, both greys or opacities rather than new hues:
  - `--control-border: #6b7380`, a grey between `--color-panel-border` and `--color-text-faint`, needed for 3:1 control boundaries;
  - `--range-fill-max: 0.45`, an opacity cap.
- **1024×768 and 1280×800:**
  - No horizontal page scroll on any page.
  - The top bar is one row on every page, also with the wide "DejaVu Sans" fallback the e2e tests force. "One row" means nothing overflows the bar and every control's box is inside the bar and the viewport.
  - On Puzzles, the table, the answer panel in every state and Submit fit the viewport with no vertical page scroll (see "Height budget").
  - What may scroll: the results details, the play analysis, Progress and Settings.
- **Accessibility:**
  - WCAG AA contrast: 4.5:1 for text, 3:1 for large text and for the boundaries of enabled controls.
  - No text below 11 px (`--text-min`) except card faces (the rank and suit drawn on a card).
  - Keyboard shortcuts, focus handling and the `?` overlay keep working.
  - A dialog traps focus, and no key reaches the page behind it.
  - `prefers-reduced-motion` is respected.
- **Dev gallery** (`/?gallery`) keeps working. Every new component gets an entry, and no entry nests `<main>`.
- **The e2e database is shared across tests:** a test that changes a setting restores it in `finally`.
- **Cross-platform:** LF line endings, no OS-specific scripts. Measured slack must hold on macOS with at least 16 px to spare, so that Windows CI font metrics still pass.
- **Checks before each commit:**
  - Backend tasks: `uv run pytest -m "not slow"`, `uv run ruff check`, `uv run ruff format --check`.

  - page widths: `--page-max-w: 100rem` (table screens, today's value), `--page-narrow-w: 72rem` (Progress), `--page-form-w: 44rem` (Settings, the Play start panel);
  - `--page-gutter: var(--space-4)` and `--prose-max-w: 72ch`;

  - type roles: `--text-page-title: var(--text-xl)`, `--text-section-title: var(--text-lg)`, `--text-card-title: var(--text-md)`, `--text-label: var(--text-xs)`;
  - the text floor `--text-min: var(--text-2xs)` (11 px);
  - `--range-fill-max: 0.45`.
- **The top bar is one row of fixed height `--bar-h` on every page** (`flex-wrap: nowrap`).
  - Left: the mark and the nav (Puzzles, Play, Progress), always at the same x. The name stays hidden below 1400 px, as today.
  - Right: each page's own controls (table below), then the Settings link last.

  | Page | Right side | Why |
  |---|---|---|
  | Puzzles | Street, Villain, `?`, New puzzle (N) | They choose the next puzzle and are used between puzzles. New puzzle is the page's main action. |
  | Play | session tally, End session, `?` | The tally is the session's state at a glance. End session is the session's only control outside the table. There is no Villain pick: the bot's profile is random per session (M10). |
  | Progress | nothing | The filters belong to the History table, and the goal to Settings. |
  | Settings | nothing | |

  - **The Settings link** is an inline-SVG gear icon link with `aria-label="Settings"` and a `title`. It has `aria-current="page"` on Settings, and is placed last on every page so it never moves. It is an SVG rather than the ⚙ glyph, which renders as an emoji on some platforms.
  - **Pot odds, Show profile and Shortcuts leave the bar for Settings.** They are set once, and they caused the wrap at 1024 (audit #1) and the crowding at 1280 (M7 item).
  - **The Villain select stays in the Puzzles bar** and edits the same `profile` setting as the Settings page (one source of truth, two places to change it; see Ruling 3).
  - **The tally** uses the sans font with `font-variant-numeric: tabular-nums` (audit #26).
- **Page headings:** every page has an `h2` page heading.
  - Progress and Settings show it at `--text-page-title`. Puzzles and Play keep it visually hidden, because the table needs the height.
  - **Focus rule:** after a click on a nav link or the Settings link (a user navigation, not the first render, not Back/Forward), focus moves to the page's heading, **unless the page has a primary focus target on show**: Next puzzle (a result is on Puzzles) or Next hand (a hand is over on Play).
  - The page's own effect places that focus. App's effect runs after PlayPage's `justShown` effect, so App must check for the primary target and not overwrite it.
  - This fixes the M7 focus item (a click on the Puzzles link left focus on the link) without breaking `play.spec.ts:82` (Next hand focused).
- `lib/page.ts`: `Page` gains `'settings'` at `/settings`, with the tab title "Settings · Poker Puzzle Trainer". Shortcuts are off on Settings and Progress, as on Progress today.

### Backend
- `Explainer.status(*, probe: bool = True, fresh: bool = False)`: `fresh=True` skips the `PROBE_TTL` cache and stores the new result. Provider `none` → `("off", None)` with no probe, as today.
- `POST /api/settings/llm-check` → `SettingsView`.
  - The body is the same as `GET /api/settings`, computed with `status(fresh=True)`.
  - It is a POST because it has a side effect: a probe and a cache write.
  - It is added to `test_contract.py` (`ROUTES`), the OpenAPI snapshot, `openapi.json` and `schema.d.ts`.
- **"Hand" noun:**
  - `build_facts(result, puzzle, log, *, subject: Literal["puzzle", "hand"] = "puzzle")` and `explain(..., *, subject=...)`, with a new field `Facts.subject`.
  - `template.GRADED_ON_RANGE` becomes `"The range in the Range tab is the range this {subject} was graded on."`.
  - The two play call sites pass `subject="hand"`: `play_service.py:632` and `play_views.py:311`.
  - The guardrail is unchanged (the sentence has no number). The explainer has no other "puzzle" wording (checked with grep over `explain/`).
- **Pot award invariant (S10):** a backend test in `test_play_views.py` checks a finished hand's `table.pot` against the stacks:
  - after a fold or a showdown, `table.pot` equals the winner's settled stack minus their pre-award stack (the last frame);
  - on a split, it is half each;
  - the cases include an all-in with unequal stacks.

  The basis is the docstring at `play_views.py:65` and the value at `:89`. If the test fails, stop and report: the frontend label in Task 9 depends on it.
- `test_static.py`: `/settings` is added to the SPA paths (nit 4).

### Contrast helper (`frontend/src/lib/contrast.ts`, Task 2)
- `parseColor(s)` reads `#rgb`, `#rrggbb` and `rgb(r g b / a%)` (and the comma form).
- `resolveTokens(cssTexts: string[]) -> Record<string, string>` reads the `:root` custom properties of the token files and resolves `var(--x)` aliases recursively. Gradients are rejected with an error that names the token.
- `composite(fg, alpha, bg)` blends a colour over a background.
- `contrastRatio(a, b)` uses the WCAG 2.1 relative-luminance formula.
- Tests read the real token files: Vitest reads them with `fs` from `src/styles/`.
