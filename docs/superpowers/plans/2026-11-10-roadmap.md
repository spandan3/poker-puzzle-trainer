# Poker Puzzle Trainer — Roadmap

**Spec:** `docs/superpowers/specs/2026-11-10-poker-puzzle-trainer-design.md`

Each milestone gets its own detailed implementation plan (`docs/superpowers/plans/`) written when the previous milestone is merged, so it can use the real interfaces. Each bullet below is one commit; every commit leaves tests green on Windows and macOS.

Repo layout: `backend/` (Python package `poker_trainer`, uv-managed), `frontend/` (Vite + React + TS), `docs/`.

## M1 — Engine core (detailed plan: `2026-11-10-m1-engine-core.md`)
1. `chore: scaffold backend package, uv, ruff, pytest, CI (windows + macos)`
2. `feat(engine): card encoding, parsing and deck`
3. `feat(engine): phevaluator wrapper with hand classes and ground-truth census`
4. `feat(engine): 1326 combos and 169 hand classes`
5. `feat(engine): weighted ranges — parsing, blockers, 13x13 grid`
6. `feat(engine): equity vs weighted range and ahead-now fraction`
7. `test(engine): equity reference values, brute-force and pokerkit cross-checks, benchmark`

## M2 — Game state and Villain model
1. `feat(game): heads-up hand state — blinds, pot/stack accounting, legal actions, street progression`
2. `feat(villain): hand categoriser and board texture / SPR features`
3. `feat(villain): profile data schema + TAG, LAG, Tight, Sticky profiles (versioned)`
4. `feat(villain): strategy — action/size probabilities per combo`
5. `feat(villain): range narrowing from the same strategy (posterior)`
6. `feat(hero): default Hero policy for earlier streets`
7. `feat(analysis): competence report script (bluff share, defence freq, dominated lines)`

## M3 — Puzzle generator and grader
1. `feat(puzzle): generator — deal, pick street/profile, play forward, frozen state with seed + profile version`
2. `feat(grader): option EVs (fold/check/call/bet/raise sizes) with labelled simplifications`
3. `feat(grader): verdicts, equity/range-read scoring, intent check, bluff check`
4. `feat(puzzle): trivial-spot filter with config thresholds`
5. `test(grader): golden hand-worked spots`
6. `test(puzzle): property tests — revealed hand in range, displayed ≡ graded range, chips conserved`

## M4 — API and storage
1. `feat(db): SQLAlchemy models (users, puzzles, attempts) + Alembic, default local user, env config`
2. `feat(api): FastAPI app — new puzzle, submit attempt, get result (Villain hidden until submitted)`
3. `feat(api): settings, history, replay endpoints; serve built frontend as static`

## M5 — Table UI
1. `chore(frontend): scaffold Vite + React + TS, lint, Vitest, dev proxy to API`
2. `feat(ui): dark theme, card graphics, oval table with seats (layout ready for 5 seats)`
3. `feat(ui): action history panel and table centre (board, pot, pot odds toggle)`
4. `feat(ui): answer panel — equity, range read, actions, sizes, intent, keyboard shortcuts`
5. `feat(ui): deal animations and puzzle flow wired to API`

## M6 — Results view
1. `feat(ui): verdict, equity/range-read comparison, options EV table`
2. `feat(ui): step-by-step maths panel`
3. `feat(ui): range grid with narrowing steps and hero-vs-range breakdown`
4. `feat(ui): Villain reveal, run-out, "judged on range" note, next puzzle`

## M7 — Progress
1. `feat(stats): store true equity, ahead-now and Hero's category with each attempt` and `feat(stats): stats service — EV-lost trend, equity/range-read error, breakdowns, streaks, daily goal` (the stats service, built in two commits: the new attempt columns and migration, then the service and `GET /api/stats`)
2. `feat(stats): leak detection rules`
3. `feat(ui): progress tab with charts, breakdowns, leaks and the daily goal`
4. `feat(ui): history table with replay and stored results` (filters, paging, a Replay and a Result button per row; retries marked "Practice")

## M8 — Explanations
1. `feat(explainer): template explanations and narrative (default provider "none")`
2. `feat(explainer): Ollama provider + number guardrail + settings status`

## M9 — Phase 1 sign-off
1. `chore: competence report reviewed and profiles tuned`
2. `docs: README with setup on Windows and macOS`

## M10 — Play vs Bots, heads-up
Spec: `docs/superpowers/specs/2026-11-12-play-vs-bots-design.md`. Full hands against one random-profile bot (the Villain policy), cash-game session with stacks carried over, optional per-hand Analyse in the M6 results-view style. Detailed plan written when M9 is merged.

## M11 — UI polish
A design pass over every screen (Puzzles, Results, Progress, Play vs Bots), the 1024×768 layout, and the polish items collected during M6–M10. Planned after M10, once every screen exists.

## M12 — Play vs Bots, 5-max (play only)
Hero + 4 bots (UTG, CO, BTN, SB, BB), each with its own random profile. Multiway game state and bot play. No analysis yet. Gets its own design pass.

## M13 — Play vs Bots, 5-max analysis
Heads-up-by-the-flop pots graded as in M10; pots with three or more players graded approximately and labelled.

## Later
- Phase 1.5: EV-guess harder mode, difficulty presets.
- Five-handed puzzles (UTG, CO, BTN, SB, BB), reusing the M12 multiway engine.
- Wider bot pre-flop tree (limps, small 4-bets) so Play vs Bots can offer them.
- Spaced repetition, daily challenge, hosted deployment, solver comparison.
