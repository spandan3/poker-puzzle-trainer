# M7 Progress Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Progress tab (main spec §10): the headline EV-lost trend (rolling 50), equity-error and range-read-error trends, accuracy by street / action / Villain profile, rule-based leaks, current and best streak, puzzles per day against the daily goal, and a history table where a click replays the puzzle (or reopens its stored result).

**Architecture:**
- **Backend:** a new package `poker_trainer.stats` (`hero.py`, `service.py`, `leaks.py`), one new endpoint `GET /api/stats?tz=<IANA>`, and three new attempt columns (migration `0003`) so stats never decode puzzle blobs. History (`GET /api/history`), replay (`GET /api/puzzles/{id}`) and stored results (`GET /api/attempts/{id}`) already exist (M4).
- **Frontend:** a page switch in `App` (`/` = Puzzles, `/progress` = Progress, `history.pushState` + `popstate`, no router library). The puzzle flow stays mounted while Progress shows, so an unanswered puzzle survives a visit to Progress. New components under `components/Progress/`. Charts are our own small SVG components (no chart library).
- **Spec:** `docs/superpowers/specs/2026-11-10-poker-puzzle-trainer-design.md` §7 item 9 (only first attempts count), §10 (progress), §11 (Progress tab, daily goal setting). Play vs Bots results stay out of these stats (Play vs Bots spec §4 "Storage and stats").
- **Previous hand-overs:** M4 "Open items" (aggregate stats, day boundary), M5 (reload during a result starts a new puzzle; the answered one is in history), M6 "Open items for M7 and later" (none are M7's; carried forward).

## Global Constraints

- **Only first attempts count** toward every stat, trend, breakdown, leak, streak and the daily count (`is_first`). Retries are counted separately (`totals.retries`) and appear in the history table with a "Practice" badge.
- **Numbers come from code and the stored grade.** Stats read stored attempt columns; nothing is regraded. EV in bb = `ev_loss_chips / 2`. Equity and range-read errors stay fractions in the API (0–1) and are shown as percentage points in the UI (`× 100`, one decimal, "pts").
- **Never decode a puzzle blob on a stats or history read.** The new columns exist for that. The stats query selects columns only (as `_summary_query` does).
- **Day boundary:** the client sends its IANA time zone (`Intl.DateTimeFormat().resolvedOptions().timeZone`) as `tz`; dates are local dates in that zone. Unknown zone → 422. Omitted → `UTC`. `tzdata` becomes a backend dependency (Windows has no system zone database; pure-Python wheel).
- **Cross-platform, dependencies, accessibility, motion, original art, commit hygiene:** as in the M5 plan's Global Constraints. No new frontend dependency.
- **Display in bb**, as everywhere.
- **Layout:** the Progress page has no horizontal scroll at 1024×768 and 1280×800 and may scroll vertically. Puzzles page layouts are unchanged (M5/M6 e2e tests stay).
- **Accessibility:** page switch links are real links (`<a href="/progress">`) in a `<nav aria-label="Main">` with `aria-current="page"`. Every chart has a text alternative: a visually hidden `<table>` (or a summary sentence plus "Show data" table) with the plotted values. Tables are real `<table>`s with `<th scope>`. History rows are activated by a real `<button>` in the row, not a clickable `<tr>`.
- Commands run from `backend/` or `frontend/` as stated.

## Decisions made in this plan

- **New attempt columns** (migration `0003_attempt_stats`, all nullable):
  - `true_equity: float | None` = `p.solution.equity`.
  - `ahead_now: float | None` = `p.solution.ahead_now` (null on the river only; pre-flop range reads are graded and stored).
  - `hero_category: str | None` = Hero's own hand category on the decision board (`HandCategory` name lowercased, the `CategoryCode` vocabulary), null pre-flop.
  - Written by `submit_attempt` from the puzzle already in memory. The migration backfills old rows by decoding each puzzle once (`decode_puzzle`); a row whose blob can't be decoded keeps nulls (stats skip nulls). The backfill sets `hero_category` only when the puzzle row's `categories_version` equals the current `load_thresholds().version`, else null (no approximate values stored).
- **`hero_category(p: Puzzle) -> str | None`** in `stats/hero.py`: `categorize(range_features(board), load_thresholds())[combo_index(*hero)]`, null when the board is empty.
- **Accuracy** = share of first attempts with verdict Best or Fine.
- **Streak** = consecutive first attempts, newest backwards, with verdict Best or Fine (`current`), and the longest such run ever (`best`). Ordered by attempt `id` (insert order).
- **Daily goal:** `today` = first attempts whose local date is today. **Day streak** = consecutive local days, ending today, with `count >= goal`; if today hasn't met the goal yet the run may end yesterday (today doesn't break it until it's over). `best_day_streak` over all days. The goal is the current setting, applied to past days too (goal history isn't stored; accepted).
- **Trend:** one point per first attempt, oldest first, the last 500 first attempts at most (`TREND_MAX_POINTS`). Each point carries the attempt's own values and rolling means over the window of the last 50 first attempts ending at that point (fewer at the start; the window is taken over *all* first attempts, so the first returned point of a capped series still averages its 49 predecessors). The range-read mean averages the non-null values in that window, null when there are none.
- **Headline:** `ev_lost_bb_last50`, `ev_lost_bb_prev50` (attempts 51–100 back; null unless there are at least 100 first attempts, so "the 50 before" is always 50), `accuracy_last50`, `equity_error_last50`, `range_read_error_last50`, all null with no attempts.
- **Breakdowns:** by `street` (pre-flop … river), by chosen `action` (fold … raise), by `profile` (`PROFILE_NAMES` order, then unknown stored names alphabetically, label = profile label if it still exists, else the stored name). Rows with no attempts are omitted. Each row: `count`, `accuracy`, `ev_lost_bb_avg`, `equity_error_avg`, verdict counts.
- **Leaks** (`stats/leaks.py`): rules over the last 200 first attempts (`LEAK_WINDOW`), so a fixed leak disappears. Each rule has a minimum sample and a threshold (module constants in one frozen dataclass `LeakThresholds`, test-visible). Output `Leak{id, kind, title, detail, count, sample, ev_lost_bb, mean_error}`. Share rules (`kind: "share"`, `ev_lost_bb` set, `mean_error` null) come first, by `ev_lost_bb` desc then `count` desc; mean rules (`kind: "mean"`, `ev_lost_bb` null, `mean_error` = signed mean) follow, by `abs(mean_error)` desc. The rules and their exact texts are in Task 3. Numbers in the text are formatted by code.
- **Endpoint:** `GET /api/stats?tz=Europe/London` → `StatsView` (schema below). `stats.service.compute(rows, *, tz, now, goal, profile_labels)` is pure (no DB) and is what tests and fixtures call; the route loads the rows and passes `now = utcnow()`. A zone the browser knows but the server's tzdata doesn't would give 422: the client then retries once with `tz=UTC` and the page shows "Days are counted in UTC (your time zone isn't known to the server)."
- **Charts:** own SVG components: `LineChart` (one or two series, y from 0, x by attempt number, gridlines, last value labelled) and `BarChart` (days vs a goal line). Sized by a `viewBox` and CSS width, so they scale without JS measuring. No tooltips in M7 (M11 polish).
- **Progress page layout** (top to bottom): a totals line "{first_attempts} puzzles answered · {retries} practice attempts" (`data-testid="progress-totals"`), then a row of tiles (EV lost/decision last 50 with the change against the previous 50, accuracy last 50, equity error, range-read error, streak current/best, today `x / goal` with day streak); the EV-lost chart (full width); equity-error and range-read-error charts side by side; the 14-day bar chart with the goal and the daily-goal input; leaks; breakdown tables (tabs Street / Action / Villain, WAI-ARIA tabs like `DecisionDetails`); the history table.
- **Empty state:** with no first attempts the page shows "No puzzles answered yet" and a "Start a puzzle" link to `/`, and no charts.
- **History table:** columns Date, Street, Villain, Your play, Best, Verdict, EV lost, Equity error; filters (Street, Verdict, Action, Villain, "First attempts only") map to the existing `GET /api/history` query params; 25 per page, Previous / Next with "x–y of n". Each row has two buttons: "Replay" (answer the same puzzle again: a practice attempt) and "Result" (reopen that attempt's stored result). Retries show a "Practice" badge.
- **Replay and stored results** (in `usePuzzleFlow`): `openPuzzle(id)` loads `GET /api/puzzles/{id}` into the answering state (the existing `loaded` message); `openAttempt(attemptId)` loads `GET /api/attempts/{id}`, then `GET /api/puzzles/{result.puzzle_id}`, into the result state through a new reducer message `opened {view, result}`. Both reuse `loadingRef` (one load at a time). Both switch the page to Puzzles. When the view's `attempts_so_far > 0`, the answer panel shows "Practice — this attempt won't count toward your stats." Opening a replay while an unanswered puzzle is on screen replaces it on screen without a warning; it isn't lost (no new puzzle row is created, so a reload resumes it via `GET /api/puzzles/current`).
- **Shortcuts** work on the Puzzles page only; on Progress they are off (except the browser's own keys).
- **Daily goal input** lives on the Progress page next to the bar chart (number 1–500, saved with `PATCH /api/settings` through `flow.setSetting`, optimistic as the other settings). Stats are refetched after a successful save (the day streak depends on the goal), so `setSetting` returns a `Promise<boolean>` (true when saved).
- **Page switch keeps the puzzle:** on Progress the play area is hidden (`hidden` attribute), not unmounted, so a half-entered answer survives. Landing directly on `/progress` defers the flow's initial load until the Puzzles page is first shown (no puzzle is generated just by opening Progress). Nav links only intercept a plain left click (no Ctrl/Meta/Shift/middle click).
- **Reload during a result** still starts a new puzzle (M5 open item, kept): the result is reachable from history now.
- **Roadmap mapping:** roadmap M7 bullet 1 is split into Tasks 1 and 2, bullet 3 into Tasks 4 and 5. The roadmap is updated in Task 5's commit.

### `StatsView` (`api/schemas.py`, all `_Out` models)

```python
class StatsTotals(_Out):      first_attempts: int; retries: int
class StatsHeadline(_Out):    ev_lost_bb_last50: float | None; ev_lost_bb_prev50: float | None
                              accuracy_last50: float | None; equity_error_last50: float | None
                              range_read_error_last50: float | None
class TrendPoint(_Out):       n: int  # 1-based first-attempt number over all time
                              attempt_id: int; created_at: str
                              ev_lost_bb: float; equity_error: float; range_read_error: float | None
                              ev_lost_bb_avg: float; equity_error_avg: float
                              range_read_error_avg: float | None
class VerdictCounts(_Out):    best: int; fine: int; mistake: int; blunder: int
class BreakdownRow(_Out):     key: str; label: str; count: int; accuracy: float
                              ev_lost_bb_avg: float; equity_error_avg: float; verdicts: VerdictCounts
class StatsBreakdowns(_Out):  street: list[BreakdownRow]; action: list[BreakdownRow]
                              profile: list[BreakdownRow]
class StatsStreak(_Out):      current: int; best: int
class DayCount(_Out):         date: str  # YYYY-MM-DD, local
                              count: int
class StatsDays(_Out):        goal: int; today: int; current_streak: int; best_streak: int
                              recent: list[DayCount]  # 14 days, oldest first, ending today
class Leak(_Out):             id: str; kind: Literal["share", "mean"]; title: str; detail: str
                              count: int; sample: int; ev_lost_bb: float | None
                              mean_error: float | None
class StatsView(_Out):        tz: str; totals: StatsTotals; headline: StatsHeadline
                              trend: list[TrendPoint]; breakdowns: StatsBreakdowns
                              streak: StatsStreak; days: StatsDays; leaks: list[Leak]
```

## Review Focus

1. **Only first attempts count:** a retry with a blunder changes no stat, streak or daily count; it shows in history with "Practice".
2. **Day boundary:** an attempt at 23:30 UTC counts on the next local day in `Asia/Tokyo` and the same day in `America/New_York`; a DST change day has the right date; an unknown zone is a 422.
3. **Rolling means:** the 51st point's average excludes the first attempt; a capped series' first point still averages 50 attempts.
4. **No blob decodes** on `/api/stats` and `/api/history` (a test patches `decode_puzzle` to raise).
5. **Charts and tables** at 1024×768: no horizontal scroll, readable axis labels, every chart has its data table for screen readers.
6. **Replay from history:** the replayed puzzle shows "Practice", its submit gives `attempt_no` ≥ 2, and the Progress stats don't change.

### Task 3: Leak detection rules (backend) — Opus

**Files:**
- Modify: `backend/src/poker_trainer/stats/leaks.py` (replace the stub)

**Interfaces:**
- Produces: `detect(rows: Sequence[StatRow], t: LeakThresholds = DEFAULT) -> list[dict]` (`Leak` shape). Only first attempts, last `t.window` (200) of them.

**Rules** (`n` = rows the rule looks at, `bad` = the rows it flags; `ev_lost_bb` = Σ `ev_loss_chips / 2` over `bad`; `count = len(bad)`, `sample = n`). A rule fires when `n >= min_n` and `count / n >= share` (or the mean condition). Percentages in texts are `math.floor(100 * x + 0.5)` (half up, not `round`); bb with one decimal; pts with one decimal.

| id | n (rows looked at) | bad | fires when | title / detail |
|---|---|---|---|---|
| `river_overcall` | river, chosen call | best is fold | n ≥ 5, share ≥ 0.4 | "Calling too often on the river" / "You called {n} river bets; folding was better {count} times ({pct}%), costing {ev} bb." |
| `overfold` | chosen fold | best isn't fold | n ≥ 8, share ≥ 0.35 | "Folding too often" / "You folded {n} times; continuing was better {count} times ({pct}%), costing {ev} bb." |
| `overbluff` | chosen bet/raise with `intent_truth == "bluff"` | verdict mistake or blunder | n ≥ 5, share ≥ 0.4 | "Over-bluffing" / "{count} of your {n} bluffs ({pct}%) were mistakes or blunders, costing {ev} bb. Check how often Villain folds before bluffing." |
| `missed_value` | best is bet/raise and `true_equity ≥ 0.6` | chosen check or call | n ≥ 5, share ≥ 0.4 | "Missing value bets" / "With a strong hand where betting was best, you checked or called {count} of {n} times ({pct}%), costing {ev} bb." |
| `draw_overestimate` | `hero_category` in strong_draw / weak_draw, `true_equity` not null | all of them | n ≥ 5, mean(guess − true) ≥ 0.08 | "Overestimating equity with draws" / "With a draw you guessed {mean} pts too high on average ({n} spots)." |
| `equity_overestimate` | `true_equity` not null | all | n ≥ 10, mean(guess − true) ≥ 0.07 | "Overestimating your equity" / "Your equity guesses are {mean} pts too high on average ({n} spots)." |
| `equity_underestimate` | same | all | n ≥ 10, mean ≤ −0.07 | "Underestimating your equity" / "Your equity guesses are {mean} pts too low on average ({n} spots)." |
| `range_read_high` | `range_read_guess` and `ahead_now` not null | all | n ≥ 10, mean(guess − truth) ≥ 0.08 | "Thinking you're ahead more often than you are" / "Your range reads are {mean} pts too high on average ({n} spots): Villain's range is stronger than you think." |
| `range_read_low` | same | all | n ≥ 10, mean ≤ −0.08 | "Giving Villain too much credit" / "Your range reads are {mean} pts too low on average ({n} spots): you're ahead more often than you think." |
| `intent_mislabel` | chosen bet/raise with an intent given | `intent_flag` not null | n ≥ 5, share ≥ 0.4 | "Mislabelling bets" / "You labelled {count} of {n} bets or raises ({pct}%) differently from what they were (value vs bluff)." |

Mean-type rules report `count = n`, `ev_lost_bb` null and `mean_error` the signed mean; `{mean}` is shown as an absolute value. Semi-bluffs aren't counted by `overbluff` (recorded as an open item).

## Follow-up after the final M7 review

Decisions made while building (controller rulings):
- Once the branch was pushed, fixes went in as separate commits instead of amends.
- The fixture's goal is 3, with a scripted gap day, so the daily-goal chart shows both met and missed days.
- Best plays are never flagged by `river_overcall`, `overfold` or `missed_value`.
- Leak text grammar: singular and plural are chosen by count.
- The mean leaks ("Overestimating your equity") have no bb cost; only the share rules show "x bb lost".
- `ev_lost_bb_prev50` needs 100 first attempts (50 + 50); before that the EV tile shows no comparison.
- Chart data is a one-sentence summary for screen readers plus a "Show data" disclosure with the table.
- One daily goal source: `stats.days.goal`. The page refetches once when the setting differs from it.
- Switching page hides the Puzzles area instead of unmounting it (a half-entered answer survives), and landing on `/progress` defers the first puzzle load until Puzzles is shown.
- `openAttempt` reads `result.attempt.puzzle_id` to fetch the puzzle.
- `bbLabel` percent fix: a label like "bet 100%" is not read as chips.
- `startedRef` first-load race fix: opening a stored puzzle counts as the first load.
- The e2e tests compare differences (the DB is shared across tests), not absolute totals.
- Backend tests for the stats fixtures live in `test_stats_fixtures.py`.

Fixed in the final fix wave: the history pager stays enabled while a page loads (clicks are ignored then), is disabled only at the ends, and moves focus to the other button when the pressed one is disabled; the range text follows the rows on show; scroll to the top on every page switch; `document.title` per page and focus on the Progress heading after a user navigation (not on first render); unique Replay and Result button names (verdict, "practice"); `openPuzzle` and `openAttempt` return a boolean and the app switches page only when true; the Villain filter lists every profile from the settings; singular totals ("1 puzzle answered", "1 practice attempt"); the leak cost rounds half up like the backend; the EV tile colour comes from the same rounded difference as its text ("same" is neutral); heading levels (page h2, sections h3, chart titles h4, hidden "Summary"); EV column with two fixed decimals; `ptsOf` renamed `formatPoints`; chart data tables render rows only while open; no shortcuts "?" button on Progress; `parse_tz` accepts only names in `available_timezones()` (less `localtime`, `Factory`, `posixrules`), so every OS accepts the same set of names (the zone data itself can differ in version between the system database and `tzdata`).
