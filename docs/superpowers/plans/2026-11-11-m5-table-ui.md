# M5 Table UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A polished, dark, keyboard-driven table screen. The user sees a puzzle exactly as the M4 API serves it (cards, board, history by street, pot, stacks, amount to call, pot odds, Villain's profile), enters an equity estimate, an optional range read, an action, a size and an intent, submits, and moves to the next puzzle. The full results view is M6; M5 ends each puzzle with a compact result strip.

**Architecture:**
- `frontend/` is a Vite + React + TypeScript app (spec §3), built to `frontend/dist`, which FastAPI already serves (M4, `PPT_FRONTEND_DIST`).
- `src/api/`: `schema.d.ts` (generated from the backend's OpenAPI by `openapi-typescript`), `types.ts` (friendly aliases), `client.ts` (typed `fetch` wrapper with an `ApiError`).
- `src/lib/`: pure logic with unit tests — `format.ts` (chips → bb, percentages, error details), `cards.ts`, `seats.ts`, `history.ts`, `answer.ts`, `shortcuts.ts`.
- `src/components/`: `Card`, `Table`, `Seat`, `TableCentre`, `HistoryPanel`, `AnswerPanel`, `ShortcutsOverlay`, `ResultStrip`, `TopBar`.
- `src/app/`: `usePuzzleFlow` (a `useReducer` state machine over the API) and `App`.
- `src/styles/`: `tokens.css` (CSS custom properties: colours, spacing, radii, shadows, motion, z-index) and `global.css`. Components use CSS Modules.
- `src/dev/`: a fixture gallery (`/?gallery`), lazy-loaded so fixtures never enter the production bundle. Entries are files in `src/dev/entries/*.tsx`, collected with `import.meta.glob('./entries/*.tsx', { eager: true })`, so parallel tasks add files without editing a shared one.

**Tech stack:** Node 22 LTS (installed in the dev environment; maintenance LTS until April 2027; `engines` `>=22.12`), npm with `package-lock.json`, Vite, React 19, TypeScript (strict), ESLint (flat config, `typescript-eslint`, `eslint-plugin-react-hooks`), Prettier, Vitest + Testing Library (`@testing-library/react`, `@testing-library/dom`, `@testing-library/user-event`, `@testing-library/jest-dom`) + jsdom, `openapi-typescript` (dev only), Playwright (dev only, end-to-end smoke test). No UI kit, CSS framework, state library, data-fetching library or animation library.

**Spec:** `docs/superpowers/specs/2026-11-10-poker-puzzle-trainer-design.md` (§3 stack and hygiene, §4 the puzzle experience, §11 UI). Roadmap: `docs/superpowers/plans/2026-11-10-roadmap.md` (M5). M4 hand-over: "Open items for M5, M6 and M7" in `docs/superpowers/plans/2026-11-11-m4-api-and-storage.md`.

## Global Constraints

- **The UI never builds an `Action`.** It sends `option` (an index from `PuzzleView.options`) or `custom_to` (chips), as M4 requires. Legal actions, sizes and labels come only from `options`. Custom sizes appear only when `custom.allowed`, bounded by `min_to` / `max_to`.
- **Nothing hidden is shown or fetched before a submit.** Before an answer the UI only calls `GET /api/puzzles/current`, `POST /api/puzzles`, `GET /api/puzzles/{id}`, settings and health. Villain's cards are face down and no undealt board card is in the DOM until the submit response arrives.
- **Display in big blinds.** Every chip amount shown is `chips / 2`, formatted by `formatBb` (`2.5 bb`, `100 bb`, never `2.50`). The API stays in chips. Custom sizes are typed in bb in steps of 0.5 and sent as `custom_to = bbToChips(bb)`.
- **Pot odds only from the API.** Show `pot_odds` when it is not null and the setting is on. Never compute pot odds from `to_call`. The amount to call is shown only when a call option exists.
- **No range read on the river.** When `range_read_asked` is false the field is not rendered and `range_read_guess` is not sent.
- **Types come from the API contract.** `src/api/schema.d.ts` is generated from `frontend/openapi.json`, which is generated from `create_app().openapi()`. A backend test fails when `openapi.json` is stale; frontend CI fails when `schema.d.ts` is stale. No hand-written response types. JSON fixtures are loaded through a typed helper `fixture<T>(name)`, because JSON imports widen string literals.
- **Cross-platform:** every dev command is an npm script or a Node script (`scripts/*.mjs`); no bash or PowerShell, no `VAR=value cmd` in npm scripts. Paths use `node:path`. Generated files are written with LF line endings. Works on Windows and macOS (CI).
- **Dependencies:** pinned through `package-lock.json` (`npm ci` in CI). Every version was published at least two weeks ago (install with `npm install --before=<today − 14 days>`). `typescript` is the newest minor inside `typescript-eslint`'s `peerDependencies` range (never the native 7.x line unless supported); ESLint's major is inside `eslint-plugin-react-hooks`'s peer range; no `--legacy-peer-deps`. The lockfile is created by a clean `npm install` with no `node_modules`, and must list the optional native packages for `win32-x64`, `darwin-arm64` and `darwin-x64` (esbuild and rollup/rolldown bindings), so `npm ci` works on every CI OS.
- **Accessibility and motion:** every interactive control is a real `<button>`, `<input>` or `<select>` with a visible focus ring and an accessible name. Cards have `aria-label`s ("Ace of hearts", "Ten of clubs", "face-down card"). Every animation is disabled under `prefers-reduced-motion: reduce`. Single-key shortcuts can be turned off (WCAG 2.1.4).
- **Original art only.** Cards, chips and the table are our own SVG and CSS. System font stack and Unicode suit glyphs only.
- **Layout ready for five seats:** seats are placed by slot (`bottom`, `bottom-left`, `top-left`, `top`, `top-right`, `bottom-right`), exposed as `data-slot`. Heads-up uses `bottom` (Hero) and `top` (Villain).
- **Desktop first:** designed for 1280×800 and up; usable at 1024 wide with no horizontal scroll; below 900 the side panel stacks under the table.
- **Backend changes are minimal and additive** (Task 1 only): `pot_before`, `amount` and `all_in` on history entries, a `dev_fixtures` module, an `openapi` dump script and its freshness test.
- Commands run from `frontend/` unless stated. Never commit `node_modules/`, `dist/`, `playwright-report/` or `test-results/`.

## Decisions made in this plan

- **History entries gain three fields** (Task 1, `api/views.action_log`, and `ActionLogEntry`):
  - `pot_before: int` = `total_pot(s)` before the action (3 for the first pre-flop entry: the blinds).
  - `amount: int` = chips moved from the actor's stack by the action (0 for check and fold).
  - `all_in: bool` = the actor's stack is 0 after the action.
- **History text is rendered by the UI, in bb,** by `entryTexts(history) -> string[]` in `lib/history.ts` (it needs earlier entries to count raises):
  - Pre-flop raise number n, counting only `raise` entries on the pre-flop street (blinds are not entries; limps never happen in the supported tree): n=1 "opens to {to}", n=2 "3-bets to {to}", n=3 "4-bets to {to}".
  - Post-flop: bet → "bets {to} ({round(100·to/pot_before)}% pot)"; raise → "raises to {to}".
  - A bet or raise with `all_in` → "all-in to {to}" (replaces the forms above).
  - Call → "calls {amount}"; a call with `all_in` → "calls {amount} (all-in)".
  - Check → "checks"; fold → "folds".
  - Amounts via `formatBb`. The server `text` stays for M8's narrative.
- **`groupHistory(view)`** returns one section per street from pre-flop to the decision street, including the decision street even when it has no entries yet. Each section carries the board cards that arrived on that street (flop 3, turn 1, river 1, from `view.board`) and its entries; the last section ends with "Hero to act".
- **Flow on load:** `GET /api/puzzles/current`; on 404, `POST /api/puzzles` with the chosen street. After a submit, `N` / "Next puzzle" POSTs. In the answering state, `N` asks "Skip this puzzle? Press N again" and a second `N` within 3 s skips (POSTs a new puzzle; the skipped one never returns, by M4's design); `Escape` cancels. A reload during the result state starts a new puzzle (the result is in history, M7) — accepted.
- **Top bar:**
  - New-puzzle street select (`Any street`, Pre-flop, Flop, Turn, River): a per-request choice kept in `localStorage` (wrapped in try/catch).
  - Villain select (`Random`, TAG, LAG, Tight, Sticky, from `GET /api/settings` `profiles`) = the stored settings profile: changing it does `PATCH /api/settings {profile}` (null = random), and `POST /api/puzzles` omits `profile`. It applies from the next puzzle.
  - Toggles "Pot odds" and "Show Villain profile" = `show_pot_odds` / `show_profile` via `PATCH /api/settings`.
  - "Shortcuts" toggle (on by default, `localStorage`) and a `?` button for the overlay.
  - Not in M5: daily goal (M7), LLM status (M8).
- **Table centre:** "Pot {pot}" where `pot` is the API's total (including bets in front of seats); each seat shows its `street_bets` as a chip stack. Five board slots: dealt cards, then empty outlined slots up to five (an empty slot never implies a card's identity). Pot odds: "Pot odds {pct}" with a hint "needs {pct} equity to call", when present and enabled.
- **Answer panel** (Task 4) is a `<form onSubmit>`; that is the only submit path.
  - **Equity:** a range slider 0–100 plus a text input (`inputmode="numeric"`, integer percent, validated), linked. Starts unset: the slider thumb is hidden and `aria-valuetext="not set"`, the text box empty; submit is disabled until it is set.
  - **Range read** ("% of Villain's range I'm ahead of now"): the same control, optional, starting in a "skipped" state with a "Skip" toggle; setting a value un-skips it. Hidden on the river.
  - **Action buttons:** always five — Fold, Check, Call, Bet, Raise. Kinds absent from `options` are disabled (`aria-disabled`, keys do nothing). The selected one has `aria-pressed`. Call reads "Call {formatBb(to_call)}". Bet and Raise select the aggressive group (only one of them can be enabled at a time).
  - **Sizes** (aggressive group selected): one button per aggressive option, labelled by `sizeLabel`: strip a leading `"bet "` / `"raise "`, `"100%"` → `"pot"`, then `· {formatBb(to)}` (the street total), e.g. `33% · 2 bb`, `pot · 6.5 bb`, `2.5x · 6 bb`, `all-in · 97.5 bb`. Selecting the group selects no size; submit stays disabled until a size or a valid custom size is set.
  - **Custom size** (only when `custom.allowed`): a text input labelled "to (bb)" with the bounds shown (`min–max bb`); invalid (out of bounds, not a multiple of 0.5, not a number) shows an inline error and disables submit. Equal to a listed option's `to` is allowed. After a 409 for this puzzle the custom input is disabled with the server's message.
  - **Intent** (value / bluff / semi-bluff): shown only for a bet or raise; optional; cleared when the action changes to a passive one.
  - **Submit:** one request; busy state; repeats ignored until the response. 409 and 422 show `formatDetail(detail)` inline (a string as is; a validation array as its `msg`s joined by "; ") and keep the answer for editing.
- **Keyboard shortcuts** (`lib/shortcuts.ts`):
  - Ignored when the event target is `input[type=text|number|search]`, `textarea`, `select` or contenteditable, except `Escape`. Active on range inputs, buttons and checkboxes. Never with Ctrl, Alt or Meta; Shift is allowed. Letters match `event.key` case-insensitively. Every handled key calls `preventDefault()` (so `E` never types "e" into the box it focuses). All shortcuts are off when the "Shortcuts" toggle is off.
  - `F` fold, `X` check, `C` call, `B` or `R` aggressive group; `1`–`9` select the aggressive group and the n-th size; `0` focuses the custom size.
  - `V` value, `L` bluff, `S` semi-bluff (only when intent is shown).
  - `E` focuses the equity box, `A` the range-read box (un-skipping it).
  - `Enter`: the global handler acts only when focus is on `body` or a non-form element and calls `form.requestSubmit()`; inside the form, native behaviour applies (Enter in a text box submits through the form; Enter on a focused button activates that button only).
  - `Escape`: closes the overlay or cancels a pending skip; otherwise blurs the focused control.
  - `N` next / skip as above. `?` (also `Shift+/`) or `H` toggles the shortcuts overlay.
  - Each button shows its key as a `<kbd>` hint and has `aria-keyshortcuts`.
- **Result strip (M5's end of a puzzle):** replaces the answer panel after a submit: verdict (colour-coded best / fine / mistake / blunder), EV lost in bb, chosen vs best option, equity guess vs true equity, range-read guess vs `grade.ahead_now` when it was asked, the revealed Villain profile, the `judged_on_range_note`, and "Next puzzle (N)". Villain's cards flip face up and the remaining board cards are dealt from `reveal.runout[board.length:]`. M6 replaces this strip with the full results view (M6.1 and M6.4 build on it; the M6 planner updates the roadmap).
- **Animations (CSS only):** hole cards deal from the dealer position with a short stagger on puzzle load (≤ 600 ms total); board cards slide in; Villain's cards flip on reveal; pot and stacks fade-update. Durations are tokens. All disabled under reduced motion. Input is never blocked longer than the deal.
- **Errors:** a top-level banner for network failures and 5xx with "Retry"; 503 from generation shows "Couldn't generate a puzzle — try again".
- **StrictMode:** the initial load is guarded by a `useRef` flag that is never reset in effect cleanup, and the initial request is never aborted. Tests render inside `<React.StrictMode>` and assert exactly one `GET /current` and at most one `POST`.
- **Fixtures:** `poker_trainer.api.dev_fixtures` (dev-only module, run as `uv run python -m poker_trainer.api.dev_fixtures ../frontend/src/test/fixtures` from `backend/`) searches seeds with predicates and drives the real app (temp SQLite DB, a seeded `puzzle_factory`) to write: puzzle views for BTN first in pre-flop; BB facing an open; facing a 3-bet; facing an all-in (fold/call only); flop unopened with no flop entries yet; facing a post-flop raise; a turn; a river; one whose history contains a 3-bet and an all-in; one with `custom.allowed`; attempt results for a bet and for a fold; and the settings view. Each file is named for its predicate; the generator is deterministic (fixed seed search order) and writes LF JSON with sorted keys.
- **OpenAPI snapshot:** `[project.scripts] openapi = "poker_trainer.api.app:dump_openapi"` writes `json.dumps(create_app(AppSettings(_env_file=None)).openapi(), indent=2, sort_keys=True) + "\n"` with `encoding="utf-8", newline="\n"` to a path argument. Backend test `test_openapi_snapshot_fresh` compares `json.loads` of the dump with `frontend/openapi.json`. (`info.version` comes from `__version__`, so a version bump needs a re-dump.) npm scripts: `gen:openapi` = `uv run --project ../backend openapi openapi.json`; `gen:api` = `openapi-typescript openapi.json -o src/api/schema.d.ts`; `check:api` (`scripts/check-api.mjs`) regenerates to a temp file and compares with `\r\n` normalised.
- **Tooling scripts:** `dev`, `build` (`tsc -b && vite build`), `preview`, `lint`, `format`, `format:check`, `typecheck`, `test` (`vitest run`), `test:watch`, `e2e`, `gen:openapi`, `gen:api`, `check:api`. ESLint and Prettier ignore `src/api/schema.d.ts`, `dist`, `playwright-report`, `test-results`. `.nvmrc` with `22`.
- **Test setup:** `@testing-library/jest-dom/vitest` matchers, `cleanup` after each test, a `matchMedia` stub. Tests drive the text inputs, not the range sliders (jsdom doesn't step sliders). The overlay doesn't depend on `<dialog>.showModal` in tests. Seat slots and suit colours are asserted through `data-slot` / `data-suit`, never CSS Module class names.
- **CI:**
  - `frontend` job on `windows-latest` and `macos-latest`: `setup-node` with `node-version-file: frontend/.nvmrc` and npm cache, `npm ci`, `npm run lint`, `npm run format:check`, `npm run typecheck`, `npm run check:api`, `npm test`, `npm run build`.
  - `e2e` job on `ubuntu-latest`: `setup-uv`, `setup-node`, `uv sync --locked` in `backend/`, `npm ci`, `npm run build`, `npx playwright install --with-deps chromium`, `npm run e2e`.
- **e2e:** Playwright `webServer` = `{ command: 'uv run --project ../backend serve', url: 'http://127.0.0.1:8765/api/health', env: { PPT_PORT: '8765', PPT_DATABASE_URL: 'sqlite:///<absolute temp file>', PPT_FRONTEND_DIST: '<absolute frontend/dist>' }, reuseExistingServer: !process.env.CI }`, paths built with `node:path`/`os.tmpdir()` in `playwright.config.ts`. Locally, the config honours `PLAYWRIGHT_CHROMIUM_EXECUTABLE` if set. The smoke test: load `/`, Hero's two cards and Villain's two face-down cards are visible, set equity, pick the first option, submit, see a verdict and Villain's cards, press `N`, see a new puzzle. A second test with `emulateMedia({ reducedMotion: 'reduce' })` asserts the card animation duration is 0.
- **Dev proxy:** Vite `server.proxy` sends `/api` to `http://127.0.0.1:8000`; `npm run dev` needs `uv run serve` running in `backend/`.

## Review Focus

1. **Contract:** no hand-written response types; `schema.d.ts` and `openapi.json` fresh (Task 1 tests).
2. **Only legal answers:** exactly the stored options plus custom sizes only when allowed; exactly one of `option` / `custom_to`; no `range_read_guess` on the river; `intent` only with a bet or raise (Task 4 tests).
3. **bb formatting:** odd chips show `.5`; no float noise; bb ↔ chips round-trips; history texts per the rules (Tasks 1, 3, 4).
4. **Shortcuts:** never fire while typing or in a select; `preventDefault` on handled keys; `Enter` can't double-submit and doesn't submit when activating a focused button; every command has a `<kbd>` hint and `aria-keyshortcuts` (table-driven test); the shortcuts toggle disables them (Tasks 4, 5).
5. **Flow:** resume, skip confirmation, next, 404/409/422/503/network handling, StrictMode single requests (Task 5).
6. **Hidden until submit:** a spying fake API proves no attempts/history endpoint is called before submit; Villain cards face down; runout cards beyond `board.length` absent from the DOM until the result (Task 5).
7. **Visual quality:** screenshots of the gallery and live app at 1280×800, 1920×1080 and 1024×768 reviewed for alignment, hierarchy, contrast (WCAG AA for text) and the spec §11 polish bar; reduced motion verified by the e2e test.
8. **Cross-platform:** Node/npm scripts only; LF generated files; lockfile has all platforms' native packages; CI green on Windows and macOS.
